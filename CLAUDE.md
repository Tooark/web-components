# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

pnpm monorepo for **Tooark Web Components**: framework-agnostic Custom Elements (`ark-*`) styled with Tailwind v4 on top of a design-token layer, plus React/Vue/Angular wrappers. Source comments and commit messages are written in Portuguese (Conventional Commits, no accents, e.g. `feat(web-components): ...`, signed off with `git commit -s`: the `dco.yml` workflow fails a PR with an unsigned commit); the README is bilingual (`README.md` / `README.pt-BR.md`) and both must be kept in sync when public behavior changes.

Requirements: Node >= 22 (CI runs on 24), pnpm 12 (pinned via `packageManager`; pnpm self-switches to it), TypeScript 6.0 (the last JS-based line; 7 waits for `@angular/compiler-cli` and `@rollup/plugin-typescript`, and Dependabot ignores its majors). Lint, formatting and import ordering are enforced by Biome (`biome.json` at the root: 120-column lines, double quotes, no trailing commas, `organizeImports` on, `noNonNullAssertion` off). The formatter cannot keep a space before the function parenthesis, so `name(): void` is the style. Since 2.6 Biome formats Markdown too, and `biome ci` fails on it: `pnpm check:fix` pads each table to its widest cell and formats the fenced code blocks with the code style (no trailing commas in the README examples); prose is not rewrapped. Suppress a deliberate violation in place with `// biome-ignore lint/<group>/<rule>: reason` (CSS uses the `/* */` form). Biome's fix for `noPrototypeBuiltins` writes `Object.hasOwn`, which the ES2020 `lib` of the Rollup packages rejects at build time; check an own property with `Object.getOwnPropertyDescriptor` instead. Type checking is `tsc --strict` inside each package build; every Rollup config sets `noEmitOnError: true` on the TypeScript plugin because by default it only _warns_ about type errors and the build still succeeds (three errors shipped that way before the flag).

### Comment convention

`/** */` documents a **symbol** — anything named that shows in the editor tooltip and survives into the bundled `.d.ts`: exported types/functions/constants, component classes, class members (including private ones), and each property of an `Ark*Options` type. `//` is everything else: the "why" behind a line or block inside a function body, the file header, and labels that group several declarations (`// --- Interação ---` in long component files, the `// Exports types ...` groupings in `packages/core/src/types/style.ts`). A label covering more than one declaration stays `//`; as JSDoc it would attach to just the first.

No JSDoc tags — `@param`/`@returns`/`@example` appear nowhere in the repo and the TS signature already states the shapes. Prose only, in Portuguese, on one line (`/** ... */`) when it fits the 120-column limit. Option types state defaults inline per property (`/** Intervalo entre itens em ms. Padrão: 60. */`), as in `packages/motion/src/types.ts`. There is no typedoc/api-extractor, so the whole payoff is the tooltip and the `.d.ts` the consumer gets; Biome has no rule for this, so it is convention plus review.

## Commands

```bash
pnpm install                                   # workspace install
pnpm build                                     # pnpm -r build (topological: tokens -> core -> web-components -> wrappers...)
pnpm --filter @tooark/web-components build     # one package (rollup + Tailwind CLI CSS + check-css smoke test)
pnpm --filter @tooark/web-components dev:css   # rebuild dist/styles.css on change
pnpm dev:storybook                             # Storybook at http://localhost:6006 (no build needed; aliases point at package src)
pnpm clean                                     # remove dist/ and storybook-static/
pnpm check                                     # Biome lint + format + import order, read-only (CI runs `biome ci .`)
pnpm check:fix                                 # apply Biome safe fixes and formatting; run before committing
pnpm check:publish                             # pack every package and run publint + attw on the tarballs (CI runs it too)
pnpm check:ssr                                 # import every dist in Node without a DOM, render the React/Vue wrappers to string (CI runs it too; build first)
pnpm version:sync                              # copy the root package.json version to every packages/*/package.json (edit the root version first)
```

Tests are Storybook stories executed by the Storybook Vitest addon in real Chromium (Playwright). Every story is a smoke test; `play` functions are the interaction tests; axe checks run via addon-a11y (currently `test: "todo"`, so a11y violations warn but do not fail).

```bash
pnpm exec playwright install chromium                                  # once
pnpm --filter storybook test                                           # whole suite
pnpm --filter storybook exec vitest run --project storybook --coverage # what CI runs
pnpm --filter storybook exec vitest run --project storybook stories/ark-switch.stories.ts           # one file
pnpm --filter storybook exec vitest run --project storybook stories/ark-switch.stories.ts -t "Toggles On Click" # one story by its display name (export split into words; the export name itself matches nothing and silently skips)
```

CI (`.github/workflows/tests.yml`) runs `biome ci .`, then `pnpm -r build` (which includes the CSS smoke test), `pnpm check:publish`, `pnpm check:ssr`, then the suite above.

### Publishing

All `@tooark/*` packages share one version (root `package.json` is the source; edit it and run `pnpm version:sync`, since `pnpm version` would also commit and tag, and the release commit is `chore(release): X.Y.Z`). `.github/workflows/release.yml` runs on every push to `main`: when `@tooark/web-components@<version>` is not on npm yet it lints, builds, runs `check:publish`, `check:ssr` and the suite, then `pnpm -r publish --access public` (topological order, `workspace:^` rewritten, Angular published from `dist/` via `publishConfig.directory`, `NPM_TOKEN` secret + provenance), tags `vX.Y.Z` and creates the GitHub Release from the matching `CHANGELOG.md` section (`scripts/changelog-section.mjs`). Prerelease versions (`1.1.0-next.0`) go to the `next` dist-tag; the optional peer floors of the wrapper subpaths (`@tooark/chart >=1.0.0`...) do not match a prerelease (semver needs `includePrerelease`), so installing a `next` side package next to a `next` wrapper package reports that peer as unmet: say so in the release notes of a prerelease, or widen the range for it. Every package has `publishConfig.access: public`, `repository.directory`, a `README.md` (English, shown on npm) plus a `README.pt-BR.md` shipped in the tarball (`files`; ng-packagr `assets` for Angular), both in the same structure as the Tooark NuGet packages (📑 contents, 📖 overview, 🔧 installation, ⚙️ configuration, 📦 components, 📝 usage examples, 📋 dependencies table generated from the manifest, 🪪 contributing, 🆘 help & security, 💖 support (GitHub Sponsors + Ko-fi, the handles of `.github/FUNDING.yml`), 📄 license; every `##` heading of every README, the root ones included, starts with an icon, `###` headings do not, and a link to a `##` heading carries the emoji's leading hyphen, `#-components`), `sideEffects` (the CSS files in tokens, core and web-components, `false` in chart, wysiwyg, code and motion; the framework wrappers do not declare it), and the Rollup packages emit both `index.d.ts` and `index.d.cts` with `exports` split by `import`/`require` (publint strict + attw pass, keep it that way). React/Vue sources import relative modules with the `.js` extension because `tsc` emits them as written and Node ESM resolution needs it. `docs.yml` deploys the Storybook to GitHub Pages on push to `main`.

### Windows notes

- pnpm may abort `pnpm run`/`build` in `runDepsStatusCheck` or hang on an interactive purge prompt. Use `$env:CI = "true"` and `pnpm --config.verify-deps-before-run=false --filter <pkg> build`; for installs, `pnpm install --config.confirmModulesPurge=false`.
- The `@tooark/web-components` build intermittently fails with `EBUSY` on `dist/styles.css`; delete that file and rebuild.
- Build one package per command: several `--filter` in one `pnpm build` left Rollup idle for minutes, and a single `--filter` run from the root has done it too, while `pnpm build` inside `packages/<pkg>` takes seconds. An idle build leaves a `rollup -c` process behind; kill it before retrying.
- The Vitest browser API port (63315) can fall inside a range Windows reserves (`EACCES`); `VITEST_BROWSER_PORT` picks another port without editing `apps/storybook/vitest.config.ts`.
- `patches/` (gitignored) holds optional pnpm patches that raise Storybook/addon-vitest test-runner timeouts for slow Windows machines. They are **not** wired into `pnpm-workspace.yaml`; the "Run tests" widget inside the Storybook UI may time out on Windows, the CLI is unaffected. Never commit `patchedDependencies` without committing the patch files.
- The "Run tests" widget in the Storybook UI keeps every story's axe report (addon-a11y) in the dev server; with full reports the server grew past the 4 GB heap and died with `JavaScript heap out of memory` after ~13 minutes (Node `DEP0205` warnings on startup are unrelated). `preview.ts` limits `a11y.options.resultTypes` to violations and incomplete, which lets the run finish (about 4 minutes, server around 2 GB); the CLI never retains the reports and stays near 1 GB. If the UI run still runs out of heap, run the CLI or start with `NODE_OPTIONS=--max-old-space-size=8192`.

## Architecture

### Layers (a package may only depend on layers below it)

```text
@tooark/react . @tooark/vue . @tooark/angular      framework wrappers (thin, one file per component; child items share the parent's file)
@tooark/web-components                             the ark-* Custom Elements + the only CSS a consumer imports
@tooark/core                                       types, i18n (en/pt/es), toast + announce services, dependency-free motion (CSS presets + WAAPI), overlay helpers
@tooark/tokens                                     tokens.css (@theme) + Ark* primitive types + JS mirrors of motion tokens + the setArkLocale store
```

Side packages: `@tooark/chart` (`ark-chart`, ECharts as peer dep), `@tooark/wysiwyg` (`ark-wysiwyg-editor`/`-viewer`, Tiptap), `@tooark/code` (`ark-code-editor`, every `@codemirror/*` package and `@lezer/highlight` as peer deps so the page keeps one `@codemirror/state`), `@tooark/motion` (opt-in helpers on the Motion lib, no element, depends on core and tokens). Chart, wysiwyg and code each ship their own `registerTooark*()` and an imperative `engine/` usable without the element, depend on `@tooark/tokens` only (no core), resolve `theme="auto"` with `resolveColorScheme` and follow runtime theme toggles with `observeColorScheme`. Apps bind them as raw tags or through the wrappers in subpath entry points (`@tooark/react/chart|code|wysiwyg`, the same in `@tooark/vue`, and Angular secondary entries in `packages/angular/<name>/` with their own `ng-package.json`); the side package is an optional peer of the wrapper package with a floor (`>=1.0.0`, code `>=1.6.0`, the version that has every type the subpath references) so upgrading a wrapper package alone raises no npm peer conflict, `typesVersions` keeps the subpaths resolvable under attw's `node10` (ng-packagr's `.npmignore` drops its nested stubs), no main-entry file may import them (`check:ssr` greps every wrapper dist file whose name lacks the subpath), and the Storybook aliases list each subpath before the main-entry alias, which would match it as a prefix. The subpath wrappers assign object and function props through the ref only when the reference changes, and the wysiwyg wrappers remember the last JSON the change event delivered (the element's `content` getter builds a new object per read), so a controlled editor keeps its cursor; the React subpaths also redeclare the raw tag in `IntrinsicElements` with the same attributes plus the JS properties (a narrower type, which interface inheritance accepts), except the wysiwyg `content`, which React already types as the `<meta>` text attribute. `framework-props.stories.ts` covers the raw tags like the core elements. They carry E2E hooks like the core components (`data-ark` + `testid`: the chart container, the wysiwyg root/toolbar/content, the CodeMirror root), and the editors forward the host's `aria-label` to their editable `role="textbox"`. In `@tooark/wysiwyg` the editor and the viewer share one extension list (`createWysiwygExtensions`), every `content` goes through `sanitizeWysiwygContent` against the schema (unknown nodes/marks dropped, `href`/`src`/`poster` restricted to http(s)/mailto/tel/relative, colors validated, programmatic `setContent` outside the undo history and without `onChange`), the toolbar is built from opt-in groups (`toolbar="style,marks,color,align,lists,link,media,blocks,clear,history"`, `all`, `none`; `role="toolbar"` with one roving tab stop, `popover="auto"` panels for colors and link positioned from the button), labels come from the package's own `i18n.ts` (no core dependency), and media only exists through the `uploadFile` hook: no hook, no `media` buttons, pasted/dropped files refused with `ark-wysiwyg-upload-error`, `<img>`/`<video>` stripped from pasted HTML (with a hook they stay only with an allowed `src`), non-media files refused with `unsupported-type`, and a hook returning `data:`/`blob:` is refused too. In `@tooark/code` the completion sources (`variableKeys`, `completions`, `completionSource`) must be created once per configuration (`EditorState.languageData.of(() => data)` with a stable `data`): autocompletion tracks queries by the source function's identity and a fresh closure per read leaves the completion pending forever. The document is always LF inside; `line-ending` (`auto|lf|crlf`) only converts at the `value`/`change` boundary. Everything added after 1.1.0 is opt-in and must stay so (an editor without the new options renders and behaves as before): the `variables` marks come from a `MatchDecorator` plugin provided through `EditorView.outerDecorations` (view >= 6.23), so each variable stays one span that the syntax highlighter, bracket matching and search marks nest inside instead of splitting (as the innermost decoration a matched `}}` cut it into five), and `.cm-ark-variable *` inherits its color into a JSON string, and `single-line` strips line breaks with a `transactionFilter` (a programmatic join goes through `applying`, so it emits no `change`). The app's own CodeMirror extensions (`extensions`, the escape hatch for grammars the package does not ship, gutters such as blame and decorations) live in one compartment at the end of the configuration, so at equal precedence the package's keymaps, gutters and language come first (`Prec.high` goes before; an app grammar needs `language="text"`, since the package's own language wins), and the element keeps the app's reference and skips a reassignment of the same one; never grow `ArkCodeLanguage` with more grammars, each would be one more peer dependency for every consumer. A story that builds extensions imports `@codemirror/*` from `apps/storybook`, whose devDependencies repeat the ranges of `packages/code` so Vite resolves the one copy the editor uses (a second `@codemirror/state` throws "Unrecognized extension value", a second `@codemirror/language` leaves the grammar unhighlighted); the `Extensions` story writes its grammar inline because `@codemirror/legacy-modes` 6.5.5 types its parsers with `@codemirror/streamparser`, which `@codemirror/language` only follows from 6.13. Tab indents through `indentWithTab` and the keyboard escape hatch is CodeMirror's own tab-focus mode (Esc then Tab, Ctrl+M or Shift+Alt+M on macOS), which reads `event.keyCode`, so stories exercise it with hand-made `KeyboardEvent`s carrying `keyCode` (user-event never sets it) and assert `defaultPrevented`. **Animation libraries must never become dependencies of `@tooark/core` or `@tooark/web-components`**; anything that needs the Motion lib goes in `@tooark/motion`.

Rollup builds ESM + CJS + a bundled `.d.ts` for tokens/core/web-components/chart/wysiwyg/code/motion, externalizing the layer below and the third-party runtime (`@tooark/core`, `@tooark/tokens`, `echarts`, `@tiptap/*`, `@codemirror/*`, `@lezer/*`, `motion`). React/Vue build with `tsc` (React adds `postbuild.mjs`, which copies `jsx-intrinsics.d.ts` into `dist/` and references it from `index.d.ts`); Angular builds with `ng-packagr` in partial Ivy (`packages/angular/ng-package.json`, published from `dist/`).

### CSS pipeline (read before touching any class string)

- `@tooark/core` compiles its own `dist/styles.css` (tokens + motion presets, no component utilities) the same way, for pages that use core without the components.
- `packages/web-components/src/styles/index.css` is the single CSS entry, compiled by the **Tailwind CLI** (not Rollup, not PostCSS) into `dist/styles.css`. It imports Tailwind's theme with `prefix(ark)`, utilities with `source(none)`, then `@tooark/tokens/tokens.css`, core's `motion.css`, `base.css` and `components.css`, and scans only `@source "../components/**/*.ts"`.
- Consequences: every utility in component code **must be written with the `ark:` prefix** (`ark:inline-flex`, `ark:hover:bg-primary-hover`, `ark:focus-visible:ring-primary-ring`); unprefixed classes are never generated. Class names must appear as complete literals in the `.ts` files (palette/size lookup tables of full strings, as in `ark-switch.ts`), never assembled from fragments.
- After compiling, `scripts/check-css.mjs` fails the build if the output still contains `@import "tailwindcss"`/`@source`/`@theme`, is too small, or lacks expected tokens/classes. When you add a class that other components rely on, consider adding it to the `--expect-class` list in the package's `build:css` script.
- No global reset ships. `base.css` applies a scoped preflight to the `:where(ark-button, ark-calendar, ...)` host list and drives theming via `color-scheme` (`theme="light|dark"` attribute). The list appears once, at the top of `@layer base`, with every rule nested inside it (flattened by Tailwind at build time). **Adding a component means adding its tag to that single list**, kept in sync with `register.ts`.
- `components.css` holds structural rules that must reach user-owned children (e.g. `ark-input > [slot="suffix"]`, `ark-carousel` slides), because components never add classes to nodes they do not own. Two of them guard stretched hosts and must keep doing so: the field grids (`ark-input`, `ark-select`, `ark-file-input`) get `align-content: start` only while a label or message is visible (`:has(> :is(...):not([hidden]))`), so a bare field still centers in a taller row (a toolbar with a bigger button), and `ark-textarea` with a visible label or message hands the extra height to the box (`grid-template-rows: auto 1fr auto`, `align-content: start` instead under `autosize`); a field with neither keeps the pre-fix layout, which `StretchedRow` checks against an inline copy of the old CSS. `ark-card` follows the same rule: `align-content: start` only while it has a heading, a header, actions or a footer, so a body-only card keeps the pre-fix layout; with those and a body of exactly one child (counted with `:has()`), that child's row is `1fr` (it fills a stretched card and the footer reaches the bottom), since CSS cannot point at the last body row of several. A `components.css` rule loses to any `ark:*` utility on the same node, so a per-instance size that must beat one goes inline from the component (the `min-height` of an `ark-textarea` with `autosize` and an explicit `rows`, since `field-sizing: content` ignores the `rows` of the `<textarea>`).
- Storybook compiles the same entry through `@tailwindcss/vite`; `preview.css` is a normal unprefixed Tailwind for story layout, deliberately proving the lib coexists with a consumer's Tailwind.

### Tokens and theming

`packages/tokens/tokens.css` defines a `@theme static` block of semantic colors (`primary|secondary|success|warning|danger|info|neutral` x `-fg/-hover/-soft/-soft-fg/-border/-ring`, plus `surface*`, `fg*`, `border*`, `muted`, `ring`), sizes (`--size-xs..xl` = 1.5/1.75/2.25/2.75/3.25 rem, the min-height of form controls), `--text-2xs` (0.6875 rem, no line-height companion, so `ark:text-2xs` only sets `font-size`: the step below `text-xs` for micro-labels such as the floating label of `xs`/`sm` fields and calendar/scheduler chips; never `ark:text-[10px]`-style literals, except the switch track labels and the calendar count badge, which are bound to their container's geometry), Tailwind's radii (`rounded` = `none|xs|sm|md|lg|xl|full`; never redefine `--ark-radius-*` outside `@theme`, it overrides the prefixed Tailwind scale) and motion tokens (`--ark-duration-*` on the eight-step scale `none|instant|quick|default|moderate|gentle|slow|long` = 0/75/150/250/350/500/700/1000 ms, `--ark-ease-linear|standard|in|out|in-out|overshoot|sheet`, `--ark-motion-distance`, zeroed under `prefers-reduced-motion`) and the code editor's syntax colors (`--ark-syntax-keyword|string|number|property|comment|atom|punctuation|invalid`, `light-dark()` pairs outside `@theme`, read by `@tooark/code` with the same values as `var()` fallbacks). Every color is `light-dark(...)`, so theme switching is pure CSS. Inside the component build these become `--ark-color-*` variables and `ark:bg-primary`-style utilities. `src/motion.ts` mirrors the motion tokens as JS constants used as WAAPI fallbacks; `src/theme.ts` exports `resolveColorScheme(element)`, which `ark-chart`, the wysiwyg elements and `ark-code-editor` use to resolve `theme="auto"` from the host's computed `color-scheme` (system preference only when the page leaves it at `light dark`), and `observeColorScheme(element, onChange)`, which they subscribe to while on `auto` (attributes of `<html>`/`<body>` plus `matchMedia`) so a runtime theme toggle re-resolves; both expose `resolvedTheme`. Custom properties outside `@theme` use the `--ark-` prefix. Continuous loaders are exempt from reduced motion by design: `.ark-animate-spin` (the button spinner) runs on a fixed `1s`, never a duration token, while attention loops stop; `.ark-skeleton` is static and `.ark-skeleton-animated` opts into the shimmer (a sweeping highlight; `ark-skeleton` phase-shifts it per block and per bar with a negative `animation-delay`).

### Component authoring pattern (`packages/web-components/src/components`)

- Subclasses of `HTMLElementBase` (`components/html-element-base.ts`, one copy per package with elements: `HTMLElement` in the browser, an empty class in Node so SSR can import the module; never `extends HTMLElement` directly, `pnpm check:ssr` fails on it), `static readonly tagName`, `static get observedAttributes()`. `registerTooark*()` is a no-op without `customElements`. Attributes are the source of truth; property getters/setters reflect to attributes, and every getter named after an observed attribute needs a setter that accepts the string a wrapper would put in the attribute (JSON for lists, `""` for booleans): React 19 and Vue assign props as properties once the element is registered, and a getter-only accessor throws in React and is silently dropped by Vue (`framework-props.stories.ts` checks every tag, `framework-wrappers.stories.ts` runs the real wrappers). `connectedCallback` builds internal DOM once (`render()`), and every change goes through a single `updateAppearance()` that rewrites `className` strings from intent/size lookup tables. Never write an **observed** attribute onto the host from inside `updateAppearance()` without checking it changed (`if (this.getAttribute("aria-label") !== label) this.setAttribute(...)`): `attributeChangedCallback` fires synchronously even for an identical value, so an unconditional set re-enters `updateAppearance()` dozens of times per render and can leave nested components half-updated (the `ark-command-palette` search field lost its placeholder this way).
- **Light DOM, never move or wrap user children.** Where the host is itself the control/container (`ark-button`, `ark-toggle`, `ark-toggle-group`, `ark-carousel` and most hosts; `ark-input` instead gets its host layout from `components.css`), component classes are applied to the host through `ownClasses` + `applyOwnClasses()` and re-applied when `class` changes, so frameworks that rewrite `class` do not wipe them. `ark-button` uses `formAssociated`/`ElementInternals` for form participation. A form-associated element is never the browser's default button (a login form with two fields did not submit on Enter), so `ark-button` adds one `document` keydown listener, in the bubble phase, that turns Enter in a text `<input>` of the form into a click on the first `type="submit"` `ark-button` (nothing when the form has a native submit button; blocked when that button is `disabled`/`loading`). A component that uses Enter inside its own `<input>` must `preventDefault()` it or the form submits: the datepicker keeps it while the popup is open or the entry is invalid, the kv-editor on the last row's value.
- **Overlays use the Popover API on the host itself** (dialog, menu, drawer in overlay mode, command palette) or on an internal node when the host stays in the flow (the tooltip bubble, the datepicker popup, the toaster stack): `popover="manual|auto"` gives the top layer, `::backdrop`, and native light dismiss + Esc for `auto`, with no portal and no `z-index` to stack overlays (`ark:z-*` never positions an overlay; a local one inside the component's own box is fine: the sticky headers of dialog, drawer and scheduler, the scheduler's now line, the input's prefix/suffix). Reset the UA `[popover]` styles (`inset`, `margin`, `border`, `padding`, `overflow`, `color`, `background`) in the host's own classes, give `::backdrop` colors a fallback in `var()`, run the exit animation before `hidePopover()`, and position anchored overlays by JS from `getBoundingClientRect()` (CSS anchor positioning is not a dependency). The helpers live in core (`packages/core/src/overlay/`): `openPopover`/`closePopover` wrap `showPopover()`/`hidePopover()` around `arkEnter`/`arkExit` (a reopen during the exit abandons it; `{ lockScroll: true }` also freezes page scroll through `lockScroll`/`unlockScroll`, reference-counted by host, which dialog, drawer and palette pass unless `no-scroll-lock`, and release again in `disconnectedCallback`), and `trapFocus` covers keyboard and pointer (Tab/Shift+Tab cycle, focus that escapes comes back to the last element focused inside, else `initial`, else the first focusable, pointer events that start outside are cancelled at capture, popovers opened on top stay usable, one on its way out through `closePopover`, still `:popover-open` during the exit animation, keeps the pointer but no longer holds the focus, nested traps stack, and the container of a trap underneath is never a popover on top: accepted as one, the dialog that opened another kept taking the focus and the clicks, `DialogBelowIsNotOnTop`). Releasing a trap returns the focus to `returnTo` in a microtask, never synchronously, and only while the focus is still in the container or on `<body>`: an overlay closed by a prop closes inside the React commit, React then refocuses the element focused before the commit (the button inside the closing overlay) and a synchronous return ended on `<body>` when the panel disappeared (`ReactOverlayClosedByPropReturnsFocus`); a `returnTo` that can no longer take the focus (the button of a dialog that closed when it opened the next) hands over to the `returnTo` of the trap that contained it. The "comes back to where it was" part is what keeps a field focused under React, which refocuses at the end of a commit the element that had the focus before it: a dialog opened by a prop focuses its field inside the commit, React hands the focus back to the opener, and a trap answering with the first focusable left it on the header's close button (two dialogs swapped in one commit left it on the button inside the closing one, then on `<body>`). The closing-popover exclusion is for focus only: applied to the pointer too, the second click of a double click on the button of a closing confirmation counted as a scrim click of the dialog below and closed it (`ClosingDialogOnTopKeepsThePointer`). Popover does not `inert` the rest of the page: a modal dialog gets `aria-modal="true"` plus that trap, and the README states the remaining limit (a screen reader's virtual cursor can still reach the page behind). An author `display` on a `[popover]` host shows it outside the top layer, so the host's `display` lives in `components.css` gated by the component's state (`ark-dialog:not([data-ark-state]) { display: none }`, `ark-menu:popover-open { display: flex }`), never in a host class. Two motion routes: `manual` popovers (dialog) animate with `openPopover`/`closePopover`; `auto` popovers (menu) cannot intercept light dismiss, so their enter/exit is a CSS transition in `components.css` on `:popover-open` (`@starting-style` in, `transition-behavior: allow-discrete` on `display`/`overlay` out) driven by the duration tokens. Anchored panels are placed by `positionAnchored` (core), which writes `left`/`top`/`transform-origin` inline and `data-ark-side`/`data-ark-align` on the panel; a menu opened at a point (`openAt`) switches to `manual` while open, because on macOS `contextmenu` fires on mousedown and the following pointerup would light-dismiss it.
- Every element calls `upgradeProperties(this)` (`components/upgrade-properties.ts`, one copy per package with elements) as the first line of `connectedCallback`: a framework can assign a property to a raw tag before `registerTooark*()`, leaving an own property that would shadow the setter after the upgrade, and the helper re-applies every own property that has a setter in the class chain, in assignment order (no list to keep). Overlays open only from `connectedCallback`: their `open` handling in `attributeChangedCallback` and in the `open` setters waits for the observer that `connectedCallback` creates, so one upgraded already open (SSR hydration, `open` assigned early) opens there. Dialog, drawer and command palette create the focus trap, choose the initial focus and emit `ark-open` in a microtask after `open` changes, always, never synchronously (`openNow` only shows the popover and records the opener, the element focused at that moment, which becomes the trap's `returnTo`): a framework that writes `open` inside its own update still moves the focus before it ends (React refocuses the element focused before the commit, so a focus chosen inside the commit went field, opener, field, and stayed on the dialog underneath when one dialog opened another), and on connect it is what lets the children connect first (an `ark-input` in the body has no `<input>` yet while the overlay's own `connectedCallback` runs) and the wrappers' listeners exist. A focus already inside the panel at that microtask is kept (an app's `useLayoutEffect`, a `focus()` right after `show()`), `openSeq` drops the microtask of an opening that was closed and redone in the same step, and a close before the microtask emits the pending `ark-open` first, so the pair stays whole (`OpenSettlesAfterTheCurrentStep` in the three story files). That choice leaves out only the host's own header (`headerEl.contains(el)`), never every `[data-ark-chrome]`: the box of an `ark-checkbox` or `ark-radio`, the button of an `ark-file-input` and the bars of an `ark-kv-editor` are chrome of their own component, and a body starting with one of them lost the focus to the footer. `EveryPropertySetBeforeRegistration` and `OverlayOpenBeforeRegistration` in `framework-props.stories.ts` check every tag.
- A component title follows `heading-level` (1–6) through `components/heading-level.ts`: `headingTag(host, fallback)` picks the tag and `retagHeading(el, tag)` swaps the node in place keeping its attributes (id for `aria-labelledby`, classes, hooks) and children (card, dialog and drawer default to `h2`, empty to `h3`).
- Call `applyTestHooks(host, "<component>", el, "<part>")` on every internal element; it sets `data-ark="<component>[-part]"` and forwards the host's `testid` as `data-testid`. The README's hooks table documents the parts and must be updated with new ones.
- Events: `CustomEvent` with `bubbles: true, composed: true`; form-like controls emit `change`, others emit `ark-*` (`ark-change`, `ark-slide-change`, `ark-event-click`...). Groups stop the child's event and emit their own consolidated one.
- Colors: use `intentColors()`/`normalizeIntent()` for token-driven inline colors; `ArkIntent`/`ArkSize`/`ArkTheme` types come from `@tooark/core`. There is no `-soft-hover` token: the `soft` variant of `ark-button` (`-soft` background, `-soft-fg` text) answers hover by showing its transparent border in the intent's `-border`, so the box never changes size.
- Boolean setters (`disabled`, `open`, `checked`, …) go through `coerceBooleanAttr` from core: React 19 sets the property when the accessor exists and the wrappers pass `""` for a present attribute, so `""`/`true` turn the attribute on and `false`/`"false"`/`null`/`undefined` turn it off. Never `Boolean(value)` in a setter.
- Sizes: `size` lookup tables cover `xs..xl`. The control height comes from the token via `ark:min-h-(--ark-size-<size>)` (plus `ark:min-w-(...)` when it must be square) and the vertical padding stays below it, so the token governs and same-size controls align (`alignment.stories.ts` asserts 24/28/36/44/52 px across button, toggle and input). `ark-switch`, `ark-checkbox` and `ark-radio` keep their own proportional tables (track and box on the spacing scale).
- Form participation for drawn controls (`ark-checkbox`, `ark-radio`; `ark-switch` shares the button + hidden input but not the rest, see the end of this item): the visual control is a real `<button role="...">` and a hidden native `<input>` (`hidden`, `tabindex=-1`) carries `name`/`value`; both are native form controls, so `<fieldset disabled>` disables them without JS (read that state with `matches(":disabled")`, not the attribute) and the host dims everything through `ark:has-disabled:opacity-50`. Accessible name in this order: `label` attribute → own `<label for>` chrome node; `aria-label` on the host mirrored to the button; user children → `aria-labelledby` pointing at the host (given a generated `id` when it has none), with a host click outside the button toggling like a `<label>`. Radios group by `name` inside the same `<form>` (the hidden input's `form`), or the same root when there is no form: one tab stop per group (the checked one, else the first enabled), arrows move focus and check, setting `checked` on one unchecks the others silently and `change` fires only on the one that gained the check. `ark-switch` is simpler: `aria-label`, else `label`, becomes the button's `aria-label` (no `<label for>`), and user children are an opt-in visible label like the checkbox's (`aria-labelledby` to the host, host click toggles outside links and controls); only while children exist does the host get classes (a flex row, the track first through `ark:order-first`, so no node moves), a switch without children keeps a bare host; it reads `disabled` from the attribute and dims only the track (`ark:disabled:opacity-50`). The host click handler of the three decides by `event.composedPath()`, never `contains(target)`: the checkbox redraws its glyph on every toggle, the clicked `<svg>` is already out of the DOM when the event reaches the host, and the box toggled twice (`userEvent.click(button)` never targets the glyph, so the story clicks the `<svg>`).
- Dates: all `YYYY-MM-DD[THH:mm[:ss]]` strings are parsed in the **local** timezone via `date-utils.ts`; never `new Date("YYYY-MM-DD")`.
- i18n: `resolveLocale(lang, localeJson?)` from core returns an `ArkLocale` (`ArkDatepickerLocale` is a compatibility alias); `lang="en|pt|es|custom"` with `locale-json` for custom strings, merged over `en`. A region tag (`pt-BR`, `es_419`, any case) picks its base language's table, here and in the wysiwyg's `resolveWysiwygLabels`; the lookup is by own property, and the public `ArkLang` type stays the four values. The datepicker's default display format keys on the exact attribute (`MM/DD/YYYY` only for `lang="en"`, `DD/MM/YYYY` for anything else, `en-GB` included): never route it through the base language, `en-GB` would flip to the US order. Without its own `lang` a component uses the opt-in default of `setArkLocale()`, kept in `@tooark/tokens` under a `Symbol.for` key on `globalThis` (the ESM and CJS copies, and the wysiwyg, which has no core dependency, share it) and re-exported by core and the three wrapper packages: pass `this.getAttribute("lang")` to `resolveLocale` (never `|| "en"`; the datepicker's format reads `getArkLocale().lang` when the attribute is absent), and call `followArkLocale(this)` right after `upgradeProperties` in `connectedCallback` and `unfollowArkLocale(this)` in `disconnectedCallback` (`components/locale-sync.ts`): one `window` listener replays a change through the host's own `attributeChangedCallback("lang", previous, next)` (`locale-json` when only custom strings changed), so it takes the same path and guards as the attribute, skips hosts with their own `lang`, and catches up on reconnect. `DefaultLocale` in `i18n.stories.ts` loops over every exported class that observes `lang` and checks that its strings change and match `lang="pt"`, so a new one that shows no strings by default needs a `SETUP` entry there. Never read `<html lang>` (refused: it would switch existing `pt`/`es` pages from English). New UI strings go into `core/src/i18n/{types,en,pt,es}.ts`, all three languages at once.
- `registerTooarkComponents()` in `register.ts` defines each element guarded by `customElements.get`; order matters where a component composes another (scheduler after toggle/toggle-group).
- Navigation (`ark-nav` + `ark-nav-item`/`ark-nav-group`): the item reuses `ark-button`'s link mode (a stretched `<a>` named by the host through `aria-labelledby`), so `href` keeps native link behavior and `ark-navigate` is cancelable only for plain clicks (modifier keys and `target="_blank"` stay with the browser); `ark-button` with `href` emits the same `ark-navigate` (`detail: { href }`) under the same rules, and also leaves `download` and a click already cancelled by the app (the old `onClick` + `navigate` workaround) to the browser; the nav propagates `variant`/`size`/`intent`/`theme` plus `data-ark-rail` (collapsed sidebar or navbar) to items and groups, which compute their own classes from it, because a `components.css` rule cannot restyle a host that carries `ark:*` utilities. In the sidebar the header, the footer and the toggle are `position: sticky` at the ends (the footer's `bottom` is the toggle's height, a per-size custom property) and a `::before`/`::after` strip paints the host padding they stop at (a `box-shadow` would be replaced by the focus ring's). The structural hides that must reach `ark-*` children (items in `collapsible="hidden"`, a badge in `slot="trailing"` on the rail, items of a closed group) are, with the tree's `icons="none"` (the user's `slot="icon"` may carry a `display` of its own), the only places `display: none !important` is used in `components.css`, each with a `biome-ignore`. The nav never positions itself; the app owns the page layout and hides its own wordmark in the rail (`ark-nav[collapsed] .wordmark`).
- Groups of user-owned controls (`ark-button-group`, `ark-radio-group`): the host is the group, the children are found by descendance (`closest("ark-x-group") === this`, so framework wrappers in between do not matter) and a MutationObserver redoes the work when children come and go. A group attribute, while present, is written onto every child and wins over the child's own (`components/group-attrs.ts`: `stampGroupAttr` keeps what the child had and gives it back when the group loses the attribute, `releaseGroupAttrs` when the child leaves; the group's observer also watches those attributes on the children, so one rewritten on a child goes back to the group's value and the rewritten one becomes what the child gets back later); "the child's own attribute wins" was the first design and cannot work, because the Vue and Angular wrappers of button and radio always write a default (`size="md"`, `variant="primary"`) on the child. Their own group wrappers therefore declare those props with no default. Joined buttons cannot be styled from `components.css` (it loses to the button's `ark:rounded-*`): the group writes `data-ark-group-pos`/`data-ark-group-dir`, which `ark-button` observes, and the button squares its own inner corners, overlaps the previous button by 1 px and, when the variant has no border, draws the divider; hover and focus raise it with a local `ark:z-10` inside the group's `ark:isolate`. Inside the group the Angular `ark-button-wrapper`, `ark-copy-button-wrapper` and `ark-radio-wrapper` become `display: contents` by a group-scoped rule in `components.css` (their host style is untouched, so nothing changes outside a group). Radios inside an `ark-radio-group` are siblings by host identity, never by `name`: a radio unchecks its siblings synchronously when it connects, the group stamps the `name` a microtask later, and two nameless groups would otherwise be the same group `""` (`NamelessGroupsStayApart`). The radio group tells apart who changed: its own `value` attribute checks the matching radio, while a `checked` mutation on a radio (the observer's attribute records) rewrites the `value`; treating both as one sync made a programmatic `radio.checked = true` revert itself. Its legend and message are prepended and placed by `order`, so a radio appended later never ends up below the message, and from its host it removes only the `aria-describedby`/`aria-invalid`/`aria-required` it wrote itself (`writeAria`), as with `aria-labelledby`.
- Tree (`ark-tree` + `ark-tree-item`): declarative and flat for assistive tech. The item host is `role="none"` and its own row chrome is the `treeitem` (focus, roving `tabindex`, `aria-level`/`aria-setsize`/`aria-posinset` set by the tree, `aria-expanded`/`aria-selected`/`aria-checked`/`aria-busy`, named by the own label through `aria-labelledby`); a nested-treeitem host with a `role="group"` gathered by `aria-owns` was tried first and axe rejected it (`aria-required-parent` on every child, axe reads the DOM parent), and `aria-owns` from the row to the user's trailing does not satisfy `aria-required-children` either, so a control in `slot="trailing"` stays a documented limit and only that story runs a11y as `todo` (the rest of `ark-tree.stories.ts` runs axe as `error`). The item host's grid lives in `components.css` (no `ark:*` display utility on it, so a collapsed branch hides its descendants with a plain descendant rule), the row band spans the grid behind the chrome, `ark-tree-item ark-tree-item` spans every column so a subitem behind the Angular wrapper's `display: contents` still lays out, and hover is gated with `:not(:has(ark-tree-item:hover))` because the hosts nest. The tree finds items by descendance (`closest("ark-tree")`, `parentItem` through wrappers), its MutationObserver recomputes the structure, and every icon write is guarded (an unconditional `innerHTML` would retrigger the subtree observer forever). The item builds its row chrome (role, name, classes, text) before inserting it, because every change after insertion is per-node work for Chromium's accessibility tree: measured with about 2,000 open nodes, mount went from 7.4 s to about 3.5 s with the accessibility tree active (under a second without it; a static ARIA tree of the same shape takes 0.4 s), while moving the level and position computation into the item made it worse. The label is `aria-hidden` (the row's `aria-labelledby` still resolves it; visible, its text would also sit loose under the tree), and the user's `slot="trailing"` becomes the row's `aria-describedby` (an `id` is given when missing). Keys with Alt, Ctrl or Meta are left to the browser. The tree observes no `lang` (no strings), so the `DefaultLocale` loop skips it. The built-in folder/file icon (`icons="files"` on the tree, `icon` on an item) is an opt-in chrome node (`data-ark-chrome="icon"`) that exists only when asked for: on first mount the item reads the tree's own attribute so the icon is built before the row is inserted, afterwards the propagated `data-ark-icons`, and every write is guarded like the chevron's. The user's `slot="icon"` wins over it, and `icons="none"` hides the user's icon too. Size and color are custom properties (`--ark-tree-icon-size` per `size` in `components.css`, `--ark-tree-icon-color` written on the host by `icon-color` and removed only if the component wrote it), never classes or inline styles on a node the component does not own; without the attributes the mount cost is unchanged (about 2,200 nodes: 147 ms either way, 231 ms with `icons="files"`).
- Toasts: `toast()` in core dispatches `ark-toast`/`ark-toast-dismiss` on `window`; `ark-toaster` listens and renders. No direct coupling between the service and the element. The stack is a `popover="manual"` shown while there are toasts and hidden when empty; each new toast re-enters the top layer (`hidePopover()` + `showPopover()`, skipped while focus is inside a toast) so it lands above overlays opened after it.
- Screen-reader announcements go through `announce(text, politeness)` from core: one hidden live-region container in `document.body` (`data-ark="announcer"`, a `role="status"`/`role="alert"` child per politeness). Components never create their own live regions, which would enter the control's accessible name or land outside the host.
- Data components (`ark-data-view`, which composes `ark-pagination`): `rows` and `columns` are JS properties and the records are kept **by reference** (events hand the app's own object back, never a copy); a cell is the field as text or what the column's `render` returns, a node or a text set through `textContent`, never `innerHTML`. The query state lives in attributes (`page`, `page-size`, `sort`, `search`, `view`): a user action rewrites them inside `changeQuery()` (one render, one `ark-query-change`), and `mode="server"` skips the search/sort/slice and only publishes. With no attribute it is a plain table with the view selector and `view="auto"`; `no-view-selector` only hides the selector, `view` (`auto`, `table`, `cards`) keeps deciding the presentation; everything else is opt-in and must stay so (`searchable`, `page-size`, `selectable`, `reorderable`, `clickable`), and what an opt-in needs is created on first use (the move menu of the reorder handle is an `ark-menu` built by `ensureMenu()`). The content is rebuilt on every `updateAppearance()` and focus goes back by part + record key (`captureFocus`/`restoreFocus`), while a selection change only patches the checkboxes (`syncSelection`). `view="auto"` follows the host's own width with a `ResizeObserver` whose reaction waits for the next frame (switching the presentation inside the callback changes the host's height and Chromium reports a ResizeObserver loop) and a hysteresis above `breakpoint`. Events of the composed controls must not leave the host: stop `change`, and also the native `input` that `ark-select` lets bubble, on each composed control, never on the host, where it would swallow the events of the app's own controls inside cells and slots. The user's slots (`toolbar`, `selection`, `empty`) are placed by the host grid in `components.css`, whose row spacing is item margin and not `row-gap`, so an empty row leaves no gap; in the DOM the component's own nodes fit around them (`arrangeChrome()`: search and sort first, selector and selection bar after the `toolbar` slot, content and footer last) so the tab order follows the visual one, and they are re-fitted, keeping focus, when a framework adds a slot child after mount. After every content redraw the host dispatches `ark-render` (it does not bubble): the hook the framework wrappers use to fill cells. Reordering has three inputs on the same handle: pointer drag (auto-scroll of the nearest scrolling ancestor in a `requestAnimationFrame` loop, and a drop mark in the primary color: an inset shadow on the cells of the target row, an `::after` line in the gap next to the target card, upright when cards sit side by side and flat when they stack, `data-ark-drop-stacked`; a rule in `components.css` loses to any `ark:*` utility on the same node, which is how an outline-based mark was silently cancelled by the card's `ark:outline-none`), arrow keys, and the move menu on click, where a keyboard click (`event.detail === 0`) always opens and a pointer click right after the menu closed does not reopen it (its own pointerdown closed the menu).

### Framework wrappers

Each of `packages/{react,vue,angular}/src` has one file per component (child items such as the menu item, the tab and the command item live in the parent's file, and a group lives in its item's file: toggle group, button group, radio group) plus `register.ts` exposing an idempotent `ensureTooarkComponentsRegistered()` (a no-op without `customElements`, for SSR). Wrapper prop types extend the `Ark*StyleOptions` types in `core/src/types/style.ts`; camelCase props map to kebab-case attributes, booleans map to `""`/`undefined`, list props (`events`, `options`, `colors`) are JSON-serialized, `localeJson` is an object only on calendar and datepicker (a JSON string elsewhere), and the kv-editor `rows` and `valueField` go in as properties (a wrapper writes `valueField` only once the app gives one, so an editor without it never rebuilds its rows on mount), like the data-view `rows`, `columns`, `selected` and `cardRender`. The data-view cells take framework content, with the same result in the three wrappers and one mechanism: the wrapper hands the element stable `render` functions that return a `display: contents` span per cell, draws into those spans, and drops the ones the element disconnected when `ark-render` fires. React draws the column's `render`/`cardRender` as JSX through portals (`flushSync` in a microtask after `ark-render`, so cells never paint empty; the `render` runs again on every wrapper render and `el.columns` is only rewritten when the column data signature changes, so inline `columns` do not rebuild the table); Vue teleports the scoped slots `cell-<key>` and `card` (or VNodes returned by a column `render`); Angular instantiates `ng-template[arkDataViewCell]`/`[arkDataViewCard]` in the wrapper's `ViewContainerRef` and moves the root nodes into the span. A column with framework content owns its cell (a `null` draws nothing); the element's "`null` keeps the field text" only holds for plain `render`. Custom events reach the handler as the `CustomEvent`, except calendar, clock, datepicker, carousel and scheduler, whose handlers get the `detail`. `ark-open` and `ark-close` bubble and are shared by dialog, drawer, command palette, menu and `ark-tab`, so those wrappers pass on only their own (`event.target === event.currentTarget`; the tabs wrapper, whose event comes from the child `ark-tab`, only an `ark-tab` whose `closest("ark-tabs")` is its host): without the check a menu closing inside an `ArkDialog` called the dialog's `onClose` and the app closed the dialog (`expectOwnOverlayEvents` in `stories/overlay-events.ts`, run by the three frameworks). A new wrapper that listens to an event name another component also emits needs the same check. So do the wrappers of the other elements that hold app content, where the component fits inside itself or inside one with an event of the same name: split pane (`ark-resize`: nested panes are a documented layout, and the outer `onResize` got the inner sizes), carousel, nav (`ark-collapse`; `ark-navigate` stays, it is the delegation of the items), nav group (`ark-toggle`, shared with `ark-tree`), tree and data view (`expectOwnContainerEvents`, same file). The check only fits an event the element dispatches on its own host. `input`/`change` on `ark-input` are the native events of the inner control and are not filtered: Vue and Angular bind them as plain listeners on the host, with no wrapper code in between, so a control of the app in `slot="prefix"`/`slot="suffix"` reaches the same handler in the three and the READMEs say to check `event.target`. Overlay wrappers (dialog, drawer, command palette, menu) attach their listeners while mounting (a template binding in Angular, a layout effect in React), because an overlay rendered open emits `ark-open` in a microtask right after it connects; `framework-wrappers.stories.ts` runs the React and Vue wrappers against react-dom and vue, and `framework-angular.stories.ts` runs the Angular ones. These `Integration/*` stories are tests only (they render an empty node), so their meta carries `tags: ["!dev", "!autodocs"]`: the suite still runs them, the sidebar and the docs do not show them. The cross-component checks `Core/Alignment`, `Core/Headings` and `Core/I18n` carry the same tags: they are not components, and the READMEs document what they check.

- React: `createElement("ark-x", { class: className, ... })`, custom events attached via ref + `addEventListener`; `jsx-intrinsics.d.ts` declares the `IntrinsicElements` typings. Every props type is wrapped in `ArkDomProps<...>` (`dom-props.ts`), which adds React's DOM attributes and handlers (`id`, `style`, `aria-*`, `onClick`...) minus the names the wrapper defines; the wrapper spreads `...domAttrs(rest)` into the element (`domAttrs` turns boolean `aria-*` into `"true"`/`"false"`, since React 19 writes `true` on a custom element as an empty attribute), so `attrs` is a `Record<string, unknown>`. `typecheck/dom-props.tsx` is compiled by the build with `tsconfig.typecheck.json` (`noEmit`) and fails it when a wrapper stops accepting them or a `@ts-expect-error` stops being an error; `typecheck/data-view.tsx` does the same for `ArkDataView`, the one generic wrapper (a cast over its `forwardRef`, so `<ArkDataView<User> />` types `columns`, `render` and `event.detail.row`; `ArkDataViewRow` is `Record<string, any>` because only an `any` index accepts an app `interface`). Every wrapper is a `forwardRef` typed with the element class from `@tooark/web-components` (imported as `ArkXElement`), so the app's `ref` reaches the element on React 18 and 19; a wrapper that needs the element itself takes `[ref, setRef] = useForwardedRef(forwardedRef)` (`use-forwarded-ref.ts`), passes `setRef` as the element's ref and keeps reading `ref.current`, and the effects list `ref` in their dependencies only because Biome cannot tell the hook's result is stable.
- Vue: `defineComponent` + `h()`, `inheritAttrs: false`, native event names re-emitted, `testid` declared as a prop. A tri-state attribute (the menu item's `checked`) is written with the `^` prefix, since Vue would turn `undefined` into `false` on the boolean property.
- Angular: standalone component with selector `ark-x-wrapper`, `CUSTOM_ELEMENTS_SCHEMA`, `[attr.*]` bindings, `@Output()` re-emitting the event, registration in the constructor, `ariaLabel` wherever the element takes `aria-label` (on the wrapper host it would miss the element), and `get element()` returning the rendered `ark-*` (typed as the element class) from `inject(ElementRef)` on the wrapper host and `:scope > ark-x`. It is `inject()`, not a constructor parameter, because Biome's `useImportType` turns an `ElementRef` used only as a parameter type into `import type`, which ng-packagr cannot inject (NG2003); `check:ssr` builds each wrapper inside an injection context and checks the tag its `element` queries. A wrapper that sits between a container and its item (`ark-command-item-wrapper`) is `display: contents`.

### Storybook specifics

`apps/storybook/.storybook/main.ts` aliases every `@tooark/*` import to the package's `src` entry (the React, Vue and Angular wrappers included, for the `Integration/*` stories), so Storybook and tests always run against source. The Angular wrappers are JIT-compiled in the browser: `main.ts` sets `oxc.decorator.legacy` (without it Vite leaves the TypeScript decorators in the output and the module fails to parse), the story imports `@angular/compiler` first, declares its host with `Component({...})(class)` and mounts it with `createApplication` + `createComponent` under `provideZonelessChangeDetection()`, calling `detectChanges()` after each change; the app's Angular devDependencies follow the versions of `packages/angular`, with `@angular/platform-browser` pinned to the exact patch the lockfile has for core (each patch peers on the same patch of core and common; `pnpm peers check` shows a mismatch). `preview.ts` imports the lib CSS from source and registers web-components, chart, wysiwyg and code. `manager.ts` sets the Tooark brand (`storybook/theming` `create()` without `base`, so the manager keeps following the OS color scheme) with `brandTitle` and no `brandImage`, which makes the manager render the title as HTML: the logo next to the version imported from the root `package.json`, so the published Storybook shows the release it documents; `public/tooark-logo.svg` (mark from the tooark.github.io site plus wordmark, colors switched by `prefers-color-scheme` inside the SVG) and `public/favicon.svg` (the site's favicon, picked up automatically because it sits at the `staticDirs` root; Biome wants a `<title>` in every SVG) live there. The page title is `Tooark Web Components`, which Storybook has no option for (`brandTitle` is only the logo's alt; the manager hardcodes `<package> - Storybook` in the HTML and `<story> ⋅ Storybook` on every navigation): `manager-head.html` swaps the name at load and on each rewrite, and the `build` script runs `scripts/storybook-title.mjs` to rewrite the static `<title>` of `index.html`/`iframe.html` (it fails the build when the tag is missing). `vitest.config.ts` sets a 30 s test timeout and `coverage.allowExternal` so coverage covers `packages/*`.

Pitfalls when writing `play` functions (each one cost a failing run):

- `storybook/test` instruments `expect`: a function passed as an argument gets wrapped, so `expect(el.formatter).toBe(fn)` fails even when the getter returns `fn`. Compare identity outside the matcher (`expect(el.formatter === fn).toBe(true)`).
- `userEvent.click` refuses an element with `pointer-events: none` (every disabled control). Dispatch the `click` directly and assert on `dispatchEvent`'s return value (`false` when the handler cancelled it).
- A demo handler that schedules a `setTimeout` (the toaster's "Loading" button fires a second toast 1.8 s later) leaks into the next story in the file and re-renders whatever it touches. In a `play`, call the service directly instead of the button, or wait the timer out inside the story.
- `PointerEvent`s made by hand work with `setPointerCapture` as long as `pointerId` is 1 (the mouse is always an active pointer); set `isPrimary: true` yourself, the constructor defaults it to `false`. `timeStamp` cannot be set, so a velocity computed from consecutive events needs a real `setTimeout` between them.
- Since 14.2 the Motion lib animates `x`/`y`/`scale` through WAAPI on the compositor, like `opacity` (before, `transform` was written from JS every frame): inline `style.transform` reads `none` from the first frame to the last, so a mid-animation check reads the computed transform (`offset()` in `ark-motion-plus.stories.ts`) and the end of an enter animation is computed `transform: none` plus computed `opacity: 1` in the same `waitFor` (`settled()` there). On completion the lib writes `transform: none` and `opacity: 1` inline, so "no inline opacity" is not a valid "revealed" check.
- CodeMirror's `hoverTooltip` reads the coordinates of a `mousemove` on the editor and user-event does not fill them: dispatch a `MouseEvent("mousemove", { bubbles: true, clientX, clientY })` at the center of the target's rect and `waitFor` the tooltip (300 ms hover delay), as `ark-code-editor.stories.ts` does.
- After `show()` or `open = true` on a dialog, drawer or palette, the focus and `ark-open` arrive one microtask later, and so does the focus return after `close()`: read `document.activeElement` inside a `waitFor` (an `await userEvent.click(...)` already yields). `data-ark-state`, `:popover-open` and `ark-close` stay synchronous; a failure there is a defect, not a timing to wait out.
- A focus check on an overlay opened by a framework needs a focused opener (`opener.focus()` or a `userEvent.click` on it) before the state change: React only hands the focus back to an element that had it, so with the focus on `<body>` the story passes with the trap broken (`ReactOverlayOpenedByPropFocusesField`).
- JS-side `prefersReducedMotion()` reads `matchMedia`; stub `window.matchMedia` in a `try/finally` (an own `matches` via `Object.defineProperty` over `Object.create(list)`, the prototype getter has no setter). CSS-side reduced motion is forced by rewriting the `@media` rules' `mediaText`, as `ark-motion.stories.ts` does.

### Dependency policy

`pnpm-workspace.yaml` pins security floors via `overrides` (Angular >= 21.2.19, postcss, nanoid, and fast-uri, which `ajv` brings in through `ng-packagr`), disables build scripts for `esbuild`/`@parcel/watcher` and allows TypeScript 6 for `ng-packagr` 21.2 (`peerDependencyRules.allowedVersions`: the Angular 21.2 compiler accepts `<6.1` and the build passes, only ng-packagr's declared peer lags; drop the rule when Angular moves to 22). The Angular peer range in `packages/angular/package.json` must stay aligned with that floor.

Dependabot never bumps the `storybook` package itself (the workspace app in `apps/storybook` is also named `storybook`), only the `@storybook/*` addons, whose peer range then asks for the newer core (`pnpm peers check` reports it). Move `storybook` in the root `package.json` to the addons' version by hand in the same PR. Its group bumps also leave stale copies behind: two `prosemirror-model` after a `@tiptap/pm` bump throw "looks like multiple versions of prosemirror-model were loaded" in the wysiwyg stories, so run `pnpm dedupe` after merging a Dependabot lockfile.
